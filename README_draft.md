Demo Project: Complete CI/CD with Terraform

Technologies used:
Terraform, Jenkins, Docker/Podman, AWS, Git, Java, Maven, Linux, Docker Hub

Project Description:
Add a provisioning stage to the CI/CD pipeline. The pipeline creates the AWS
server by itself, instead of deploying to a server that already exists.

Steps (from the task):
- Create SSH key pair
- Install Terraform inside the Jenkins container
- Add Terraform configuration to the app's git repository
- Update Jenkinsfile to add a "provision" step
- Full pipeline:
  a. CI: build the Java Maven app
  b. CI: build and push the Docker image to Docker Hub
  c. CD: provision an EC2 instance with Terraform
  d. CD: deploy the new app version to the EC2 instance

Requirements:
- Jenkins Maven tool
- A container runtime (Podman or Docker)
- Git PAT
- OCI credentials: a separate Jenkins Username/Password credential, with
  Docker username and a read-write PAT
- AWS_CRED_ID: a separate Jenkins Username/Password credential, with the
  IAM user's aws_access_key_id (as username) and aws_secret_access_key
  (as password)
- Terraform binary must be on the Jenkins agent

Notes / what I found in the repo while writing this draft:
- Jenkinsfile stages, in order: init -> Java Maven code build -> Container
  Image Build -> AWS Infra Deploy w/ EC2 -> Deploy App to EC2/Podman
- utils.groovy has the real logic behind every stage: buildMvn,
  buildContainerImage, createContainerFile, iacDeploy, deployApplication
- Terraform code lives in extras/01_IaC_Automate_AWS_infra (VPC + EC2
  module). extras/02_IaC_Automate_EKS_provision is a different exercise,
  not part of this project.
- The app is a small Spring Boot app (src/main/java/com/example), it gets
  packaged as a jar and runs inside a container.
- No Containerfile is checked into the repo (I had one to try something,
  removed it). It is generated by utils.groovy (createContainerFile)
  during the pipeline run.
- Terraform creates an Ubuntu 22.04 EC2 instance and installs Podman on it
  with user_data.
