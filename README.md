# Java Maven App – CI/CD with Jenkins, Podman and Terraform

This project is a complete CI/CD pipeline for a small Java Maven app. The
pipeline builds the app, builds and pushes a container image, and then
creates its own AWS server with Terraform and deploys the app on it. So the
server is not created by hand before. The pipeline creates it every time.

## What the pipeline does

1. Build the Java Maven app and create the jar file.
2. Build a container image with Podman and push it to Docker Hub.
3. Provision an EC2 instance on AWS with Terraform (VPC, security group,
   and the instance itself).
4. Connect to the new EC2 instance with SSH, pull the new image, and run
   it with Podman.

## Technologies used

Terraform, Jenkins, Podman/Docker, AWS, Git, Java, Maven, Linux, Docker Hub

## Pipeline stages

The pipeline is defined in `Jenkinsfile`. The real work for each stage is in
`utils.groovy`.

| Stage                         | What it does                                              | Function in utils.groovy |
|-------------------------------|------------------------------------------------------------|---------------------------|
| init                           | Reads the app version from Maven, builds the image name    | –                         |
| Java Maven code build          | Runs `mvn clean package`                                    | `buildMvn()`              |
| Container Image Build          | Creates the Containerfile, builds the image, pushes to Docker Hub | `buildContainerImage()` / `createContainerFile()` |
| AWS Infra Deploy w/ EC2        | Runs `terraform init/validate/apply` to create the EC2 server | `iacDeploy()`             |
| Deploy App to EC2/Podman       | SSH into the server, pulls the new image, runs it with Podman | `deployApplication()`     |

## Repository structure

```
Jenkinsfile                              # pipeline definition
utils.groovy                             # pipeline logic (build, deploy, provision)
pom.xml                                  # Maven config for the Java app
src/main/java/com/example/Application.java  # small Spring Boot app
extras/01_IaC_Automate_AWS_infra/        # Terraform code (VPC + EC2, used by this project)
extras/02_IaC_Automate_EKS_provision/    # a different exercise, not part of this project
```

## Before you run it

You need these things ready on the Jenkins side:

- Jenkins Maven tool configured (name: `Maven`)
- A container runtime on the Jenkins agent (Podman or Docker)
- Terraform binary on the Jenkins agent
- A Git PAT (personal access token), to work with the repository
- A Jenkins "Username/Password" credential for Docker Hub, with your
  Docker username and a read-write PAT (id used in Jenkinsfile:
  `dockerhub-pat-rw`)
- A Jenkins "Username/Password" credential for AWS, with the IAM user's
  `aws_access_key_id` as username and `aws_secret_access_key` as password
  (id used in Jenkinsfile: `aws_iam_user_access_key`)
- A Jenkins SSH credential for the EC2 instance's key pair (id used in
  Jenkinsfile: `ec2_pem_for_ubuntu`)
- An AWS key pair with the same name as `EC2_KEY_PAIR_NAME` in the
  Jenkinsfile

## Main environment variables (in Jenkinsfile)

| Variable            | Meaning                                      |
|---------------------|-----------------------------------------------|
| `CONTAINER_RUNTIME`  | container tool used on the Jenkins agent (podman) |
| `BASE_IMAGE`         | base image for the app's container            |
| `OCI_REG_ADDR`       | container registry address (docker.io)        |
| `INSTANCE_TYPE`      | EC2 instance type (t3.micro)                  |
| `REGION`             | AWS region (us-east-1)                        |
| `EC2_KEY_PAIR_NAME`  | AWS key pair name, used by Terraform and SSH  |

## Notes

- There is no `Containerfile` checked into the repo. It is generated by
  `createContainerFile()` in `utils.groovy`, during the build.
- The Terraform code creates an Ubuntu 22.04 EC2 instance and installs
  Podman on it automatically (see `user_data` in
  `extras/01_IaC_Automate_AWS_infra/modules/vpc/30-instance.tf`).
- This is a learning project, built while following a DevOps course
  (Terraform / Infrastructure as Code module).
